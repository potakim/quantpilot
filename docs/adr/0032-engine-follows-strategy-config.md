# 0032 · 엔진이 전략 설정(켜기/끄기·배분·파라미터)과 AI 판단 설정을 따른다

상태: 승인 (2026-10-04)

## 맥락
2026-10-04 화면 점검(t35)에서 확인했다. 화면과 API에서 바꾸는 값을 실시간 엔진이 하나도 읽지 않는다.

1. **전략 설정**:
   - 엔진은 `build_upbit_paper(("vol_breakout",))`로 전략을 기본 파라미터로 만들어 돌린다.
   - `strategy_configs`의 `enabled`·`allocation`·`params`는 저장만 되고 엔진은 읽지 않는다. 대시보드에서 전략을 꺼도 엔진은 계속 산다.
2. **사이징**:
   - 수량은 "목표 비중 × 판단 배수 × 계좌 평가액"으로 계산한다(`TickRunner._size`). 문서의 정의는 "비중의 기준 = 배정 자본(총 자본 × allocation)"(05 §1, 00 용어)이다.
   - 변동성 돌파는 코인 하나에 최대 20%(`max_weight / 5코인`)를 잡는다. 같은 날 여러 코인이 돌파하면 뒤에 오는 코인은 단타 합산 상한(20%)에 걸려 줄거나 거부될 수 있다.
3. **AI 판단 설정**:
   - `PATCH /settings`의 `gate.hold_below`·`gate.full_above`·`judge.provider`·`llm.models`는 DB에 저장된다.
   - 엔진은 시작할 때 환경변수(`QP_GATE_*`, `QP_JUDGE_PROVIDER`, `QP_LLM_PROVIDERS`)로만 파이프라인을 만든다.
   - `judge.provider=laya`는 저장은 되지만 배선되지 않았다(`build_pipeline`이 거부한다).
4. **설정 행이 없을 때**:
   - API는 "기본값·비활성"(allocation 0)으로 보여 준다.
   - 엔진이 신호를 기록하면 `EventRecorder.signal`이 allocation 0·켜짐 행을 만든다.
   - 두 규칙이 서로 다르다.

## 결정
1. **기본 설정** (`strategies.DEFAULT_CONFIG`, `strategies.strategy_config()`):
   - 설정 행이 없는 전략은 코드 기본값을 쓴다. 값은 화면 원본의 권장 조합이다.

     | 전략 | 켜짐 | 배분 |
     |---|---|---|
     | 변동성 돌파 | 켜짐 | 15% |
     | GEM | 꺼짐 | 40% |
     | GTAA | 꺼짐 | 35% |
     | ORB | 꺼짐 | 0% |

   - GEM·GTAA·ORB는 2단계 시장(ADR 0031)이라 기본으로 꺼 둔다. 2단계에서 엔진을 붙였을 때 저절로 사지 않게 하려는 것이다.
   - API 표시, 배분 합 검사, 신호 기록 때 만드는 행, 엔진이 모두 이 함수 하나를 쓴다.
2. **엔진의 설정 동기화** (`MarketEngine._sync_configs`, `SettingsEngineLink.strategy_configs`):
   - 엔진은 시작 직후(`restore`)와 하트비트마다(5초) 자기 시장의 전략 설정을 읽어 `TickRunner.apply_configs`로 넘긴다.
   - 엔진은 자기 시장에 등록된 전략을 모두 만든다(1단계 업비트 = 변동성 돌파). 켜기/끄기는 설정으로만 정한다.
   - `apply_configs`를 한 번도 부르지 않은 `TickRunner`(백테스트)는 모든 전략이 켜짐·배분 1.0이다. 그래서 백테스트·G1 결과는 바뀌지 않는다.
3. **꺼진 전략과 배분 0** — 진입만 막는다:
   - `enabled=false` 또는 `allocation=0`인 전략에서 비중을 늘리는 target은 버린다. 판단 모델도 부르지 않는다.
   - 청산(비중 0)·축소·손절·시간 청산은 그대로 처리한다(불변식 #6의 정신과 같다: 청산은 막지 않는다).
   - 꺼진 전략의 평가는 규칙 미충족 집계(ADR 0027)에 넣지 않는다.
4. **배분 사이징**:
   - 사이징 기준은 "계좌 평가액 × 전략 배분"이다. `Target.weight=1.0`이 배정 자본 전부다(05 §1).
   - 진입 판정(`_increases`)도 같은 기준을 쓴다.
   - 리스크 검사(`RiskManager.check`)에는 지금처럼 계좌 전체 평가액을 넘긴다. 종목·단타 상한과 서킷브레이커의 기준은 바뀌지 않는다.
5. **자본 기준**:
   - 계좌 평가액은 그 전략 시장의 계좌다. ADR 0020의 전략별 손익 기준(allocation × 시장 월초 평가액)과 같다.
   - 1단계는 업비트만 돌기 때문에(ADR 0031) 시장 계좌 = 총 자본이다. 화면의 "총 자본"도 같은 값(`/portfolio` total)을 쓴다.
   - 두 번째 시장을 붙이는 2단계에서 다시 정한다. 계좌를 배분대로 채우거나, 총 자본 기준으로 바꾸는 방법이 있다.
6. **파라미터**:
   - 설정의 `params`가 바뀌면 엔진이 그 전략을 새 파라미터로 다시 만든다. 만들 때 검증에 실패하면 이전 것을 유지하고 오류를 남긴다.
   - 대상 종목(`symbols`)은 시세 구독이 시작할 때 정해지므로 이 카드에서는 엔진에 반영하지 않는다. 화면에서도 바꾸지 않는다.
   - G1은 기본 파라미터로 검증하므로, 화면은 파라미터가 기본값과 다르면 그 사실을 표시한다.
7. **AI 판단 설정**:
   - **확신도 임계값**은 엔진이 하트비트마다 읽어 판단 파이프라인에 바로 반영한다. 범위를 벗어난 값은 무시하고 경고만 남긴다.
   - **판단 모델·LLM 리뷰어**는 엔진이 시작할 때 settings 표 값을 환경변수 위에 덮어써서 파이프라인을 만든다. 저장 후 엔진을 재시작해야 적용된다.
   - 엔진은 실제로 쓰는 판단 모델·리뷰어를 `engine.judge.<market>`에 쓴다. 화면은 저장값과 이 값이 다르면 "재시작 후 적용"을 보여 준다.
   - `PATCH /settings`는 키가 없는 모델(TypeSafe ↔ `typesafe_api_key`, claude ↔ `anthropic_api_key`, gemini ↔ `google_api_key`)과 배선되지 않은 `laya`를 400으로 거부한다. 재시작한 엔진이 쓸 수 없는 모델을 고르지 못하게 한다.
   - 키가 있는지는 환경변수와 키 파일(`data/keys.env`, ADR 0017)로 판단한다.
   - `GET /settings`는 지금 유효한 판단 설정(`judge`: 판단 모델·리뷰어·임계값·키 유무)을 함께 돌려준다.
   - 시작할 때 덮어쓴 설정으로 파이프라인을 만들지 못하면 환경변수 설정으로 되돌리고 CRITICAL 로그(텔레그램)를 남긴다. 엔진이 재시작을 되풀이하지 않게 한다.

## 결과
- 화면의 켜기/끄기·배분·파라미터·임계값이 실제 엔진 동작이 된다. 화면이 엔진과 다른 말을 하지 않는다.
- 변동성 돌파의 기본 배분은 15%다. 코인당 비중은 최대 3%(합 15%)로, 단타 상한(20%) 안에서 다섯 코인이 모두 들어간다.
  - 이 카드 전에는 계좌 전체를 기준으로 사서, 첫 진입이 클수록 뒤 코인의 진입이 막혔다. 이제 같은 신호의 주문 금액이 기본값 기준으로 15%가 된다.
- 백테스트·G1은 배분을 쓰지 않으므로 수치가 바뀌지 않는다(t35에서 전후 비교로 확인).
- 배포 직후에도 변동성 돌파가 권장 배분으로 페이퍼 매매를 시작한다. 체크리스트에 따로 할 일이 없다.
- 판단 모델을 바꾼 뒤에는 엔진 재시작이 필요하다. 화면이 그 상태를 보여 준다.
